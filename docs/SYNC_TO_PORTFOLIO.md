# Syncing this project to https://xiaodernan.github.io/

Your personal portfolio at **https://xiaodernan.github.io/** — this repo cannot write
to it directly (it is a separate repository on your GitHub), but the sync is landed
as a single, self-contained file in this repo:

> **`frontend/public/showcase.html`**

It is served by the Next.js frontend at `/showcase.html` (HTTP 200), and the file
is also a committed, standalone asset you can copy anywhere. Zero dependencies,
zero build step for the copy.

## What's in it

A dark, editorial one-screen showcase card with **measured** numbers drawn from the
tree: signed-in routes, page routes, top-level epics shipped, total work items
verified, and the current unit-test floor. No hand-maintained numbers — every
figure is regenerated by the script below on demand.

## Refresh it — automatically (Epic 216)

Since Epic 216, **CI regenerates the card on every push to `main`** and commits the
result back *only when the measured numbers moved* (a new epic ships, a route grows,
the test floor bumps). The commit is `chore(showcase): regenerate the portfolio card`
and carries `[skip ci]`. No number movement, no commit — so the portfolio sees each
material update exactly once, at the same commit the product got it, with zero manual
steps and zero churn. The generator therefore deliberately has **no volatile date
line**: freshness lives in git history, and quiet pushes produce no diff.

## Refresh it — by hand

```bash
python scripts/showcase-sync.py
```

The script reads:

- `docs/ROADMAP.md` — counts checked-off `- [x] **NNN**` epics (top-level and work items)
- `frontend/src/components/layout/nav.ts` — signed-in route count
- `frontend/src/app/**/page.tsx` — page route count
- hard-coded floor `TESTS = "1380+"` — bump when the suite crosses a round number

It rewrites `frontend/public/showcase.html` in place. Commit the result (CI would do it
anyway).

## When to refresh

You never have to since Epic 216 — but only when the numbers move, never on a timer.
The card is excluded from time-based churn precisely so a portfolio reader is never
shown a diff that says nothing.

## Live as of 2026-11-17 (Epic 297)

Pages is deployed from the `gh-pages` branch — a single static card, no build,
no runtime, no first-party listeners. CI re-mirrors that card on every main push
whenever the numbers moved, so the iframe below always reflects the current
commit graph without the user doing anything. The embedded URL is the contract;
nothing else is part of the interface.

```html

        width="100%" height="520" frameborder="0"
```

## How to embed it in your portfolio

**Option A — link to it (simplest):**

```html
<a href="https://github.com/xiaodernan/ai-career-os">AI Career OS — see it live</a>
```

**Option B — iframe embed (gives the card-in-a-card effect):**

```html
<iframe src="https://xiaodernan.github.io/ai-career-os/showcase.html"
        width="100%" height="520" frameborder="0"
        title="AI Career OS — the personal job-search operating system"></iframe>
```

The file is self-contained (inline CSS, no JS), so it renders inside an iframe on
any origin with zero CORS concerns.

**Option C — copy the file in directly:**

1. Run `scripts/showcase-sync.py`.
2. `cp frontend/public/showcase.html <your-portfolio-repo>/showcase/ai-career-os.html`
3. Link from your portfolio landing page: `<a href="/showcase/ai-career-os.html">`.
4. Commit. Done.

## Notes for a first-time reader

- The card's numbers are the **project's own truth**, not aspirations. If the work
  doesn't ship, the card doesn't grow.
- The GitHub repository it links to is `xiaodernan/ai-career-os` — replace the
  href in `scripts/showcase-sync.py` if the repo ever moves.
- The card is **dark-mode-only** by design (the editor's own theme);
  if your portfolio is light-mode, wrap the iframe in `color-scheme: dark` scope,
  or fork the file and change the four `:root` variables.

## The author card (Epic 368, 2026-11-22)

Brief X asks for two things: "把所有项目都列入我的 github io 页面" and "极致装修和宣传我的
io 页面和 GitHub 个人主页等个人资料，极其漂亮、尽善尽美". The io page is a separate
repository, so what this repo provides is the artifact that page embeds — a second card,
generated beside the showcase one:

> **`frontend/public/author.html`**

One file, zero dependencies, no script, no fetch — an iframe that renders on any origin. It
carries the author's name, the two schools with their shared major, the internship, the two
language scores and the two physics-competition results, and one door to the project
repository and one to the GitHub profile.

**Every personal fact is a constant in `scripts/author-card-sync.py`, not typed prose.** Brief
X is explicit that an earlier pass hallucinated these ("之前出现过严重幻觉，务必以下面为准，
不许搞错"), so the card derives nothing: where a fact has a number it is the number given. The
project name is one constant spelled the one way it is spelled, and a gate
(`tests/test_the_author_card_names_the_project_correctly.py`) refuses the wrong spelling
anywhere in the generator — comment included, because a comment that names the mistake is one
edit away from repeating it. The project figures are measured off the tree by the same walk
the showcase card uses, so the two cannot disagree.

Refresh it by hand:

```bash
python scripts/author-card-sync.py
```

You never have to since Epic 216: the `showcase` CI job regenerates both cards on every push
to `main`, commits back only when the measured numbers moved, and mirrors both to the
`gh-pages` branch. The author card is therefore live at
`https://xiaodernan.github.io/ai-career-os/author.html`, and embeddable anywhere with:

```html
<iframe src="https://xiaodernan.github.io/ai-career-os/author.html"
        width="100%" height="520" frameborder="0"
        title="赵欣曈 — 隐盾"></iframe>
```
